# Phase 3 — Academic Data & Real Canvas Pages Implementation Plan

> **For agentic workers:** Execution method supplied by the user: implement natively, task by
> task, after this plan is approved; stop after Phase 3 for review. Steps use checkbox syntax.

**Goal:** Replace the Phase 2 placeholder seed with a realistic, deterministic Linear Optimization
course stored as Canvas REST API JSON. Load it through a real ingestion layer, and render every
Canvas tab from that data for students and the teacher.

**Architecture:** A generator writes `data/seed/**` (Canvas JSON, manual JSON, PDFs), and its
output is committed. `npm run seed` rebuilds `data/app.db` by running
`CanvasJsonAdapter` + `ManualAdapter` → canonical Pydantic models → `loader`. The API adds
read-only routers, and every visibility rule lives in `app/auth.py`. The web app adds real pages
built with InstUI.

**Tech Stack:** unchanged from Phase 2, plus **fpdf2** (generator only). See §6.

**Spec:** the Phase 3 prompt (this conversation) + `docs/PHASE1_PLAN.md` §4.3, §5.1, §5.2, §5.4
(grade-related parts only).

## Global Constraints

- No AI, analytics, mastery, diagnoses or recommendations. No §5.3 tables. Learning Insights and
  Instructor Analytics stay placeholders.
- No Canvas REST client (Phase 4), no grading/editing UI, no quiz-taking, no upload, no real auth.
- Every table that can come from Canvas keeps `source` + `external_id`.
- `question_outcomes.source ∈ {'canvas_alignment', 'instructor'}` (DB CHECK constraint).
- Generator is deterministic: `random.Random(3200)`, fixed PDF creation dates, sorted JSON keys.
  Two runs must produce byte-identical output.
- Demo user ids stay stable: 1 = Prof. Dana Rivera, 2 = Alex Kim, 3 = Priya Natarajan,
  4 = Marcus Bell.
- PDFs are shown with the browser's native viewer (`<iframe>`), not pdf.js.
- All permission decisions go through `app/auth.py`.

## Review Focus

1. A student requests another student's submission by id → **404** (we don't confirm that it
   exists). Same for that submission's PDF via `/api/files/{id}/content`. (Task 5 tests)
2. A student opens an upcoming quiz → sees the description, but **no questions and no answer
   key**. Opening a submitted-but-ungraded HW3 → no score, no answer key, no comments.
   (Task 5 tests)
3. A teacher-only comment exists on a graded submission the student owns → it never appears in
   any student response (submission, grades, course home). (Task 5 tests)
4. A course has an assignment group with weight but no graded work (Final Exam) → the current
   grade renormalizes over the groups that have graded work instead of counting it as 0.
   An excused submission is left out, and a missing submission graded 0 counts.
   (Task 4 tests)
5. The PDF iframe can't send the `X-Demo-User` header → auth also accepts a `demo_user` cookie
   that the web app sets on every switch. The header wins if both are present. (Task 5 test)

## 2. API endpoints and permission rules

Identity: `current_user()` reads `X-Demo-User`, falling back to the `demo_user` cookie.
"Enrolled" = any enrollment in the course (`require_enrolled`), and "Teacher" =
`require_teacher`. **Self** = the student who owns the resource. Every student-facing payload
passes through the visibility helpers in `auth.py`:

- `student_can_see_questions(submission)` → True once the student has submitted.
- `student_can_see_results(submission)` → True only when `workflow_state == 'graded'`. This gates
  scores, correctness, answer key, rubric scores and feedback.
- `visible_feedback(rows, enrollment)` → drops `visible_to_student = False` rows for students.

| Method & path | Who | Student view vs teacher view |
|---|---|---|
| `GET /api/health` | anyone | |
| `GET /api/demo/users` | anyone | now `{id, name, sortable_name, roles: ["Teacher"]}`, sorted teachers first, then by sortable name |
| `GET /api/me` | any user | |
| `GET /api/courses` | any user | own enrollments only |
| `GET /api/courses/{cid}` | Enrolled | |
| `GET /api/courses/{cid}/home` | Enrolled | student: upcoming (next 14 days + undated), recent visible feedback on own graded work. Teacher: upcoming + count of submissions still ungraded per assessment |
| `GET /api/courses/{cid}/syllabus` | Enrolled | syllabus_html, outcomes, course summary rows (title, kind, due_at, points) |
| `GET /api/courses/{cid}/assignment_groups` | Enrolled | groups + weights + assessments. Student rows carry own status/score (score only if graded) |
| `GET /api/courses/{cid}/assessments/{aid}` | Enrolled | teacher: questions + answer keys + aligned outcomes + rubric. Student: rubric criteria always; questions only if `student_can_see_questions`; answer keys only if `student_can_see_results`; `my_submission_id` |
| `GET /api/courses/{cid}/assessments/{aid}/submissions` | Teacher | all students incl. unsubmitted, with score/state |
| `GET /api/courses/{cid}/submissions/{sid}` | Teacher, or Self | Another student → **404**. Self: responses/scores/rubric/feedback gated as above |
| `GET /api/courses/{cid}/users/{uid}/grades` | Teacher, or Self | grade summary: per-assessment rows + per-group % + weighted current grade |
| `GET /api/courses/{cid}/gradebook` | Teacher | students × assessments grid with submission ids |
| `GET /api/courses/{cid}/materials` | Enrolled | course materials grouped by module |
| `GET /api/files/{fid}/content` | Enrolled in file's course; if `owner_user_id` is set: Teacher or that owner (else 404) | `FileResponse`, `Content-Disposition: inline` |
| `GET /api/courses/{cid}/analytics/summary` | Teacher | unchanged placeholder |

Unknown course → 404. Not enrolled → 403 (as in Phase 2).

## 3. Seed course outline

**Main course:** ISE 3200 – Linear Optimization, Autumn 2026 (Aug 25 – Dec 9), Prof. Dana
Rivera. 20 students: ids 2–4 (Alex Kim – average with a recurring slack-sign error; Priya
Natarajan – strong; Marcus Bell – struggling) + 17 new fictional students, ids 5–21. Mix:
5 strong, 10 average, 5 struggling. One missing submission (Quiz 2, graded 0), one excused
(HW1).

**Second course:** STAT 1450 (unchanged identity). Rivera + students 2–4, 2 outcomes, 2
assignments (1 graded homework, 1 upcoming quiz), 1 reading, short syllabus.

**Outcomes (ISE 3200)** — written into the syllabus as "Learning Objectives":

| Code | Objective |
|---|---|
| LO1 | Formulate linear programs from word problems (decision variables, objective, constraints) |
| LO2 | Convert LPs to standard form (slack/surplus variables, non-negativity, free variables) |
| LO3 | Solve two-variable LPs graphically and interpret corner points |
| LO4 | Carry out the simplex method (entering/leaving variables, ratio test, degeneracy, unboundedness) |
| LO5 | Formulate the dual and apply complementary slackness |
| LO6 | Interpret sensitivity analysis (shadow prices, reduced costs, ranging) |

**Assignment groups:** Homework 30% · Quizzes 20% · Midterm 25% · Final Exam 25% (no
assessments yet, which exercises renormalization).

**Assessments** (42 scored leaf questions; "today" ≈ Oct 24):

| Assessment | Group | Due | State | Points | Leaf Qs (parts) | Rubric | Outcomes | Evidence source |
|---|---|---|---|---|---|---|---|---|
| HW1 Modeling & Graphical Method | Homework | Sep 12 | graded | 40 | 6 (Q1a–c, Q2a–b, Q3) | – | LO1, LO3 | typed PDF upload + manual per-question scores |

| Quiz 2 Simplex Mechanics | Quizzes | Oct 3 | graded | 10 | 5 | – | LO2, LO4 | Canvas quiz |

| Quiz 3 Duality | Quizzes | Nov 7 | upcoming | 10 | 5 | – | LO5, LO6 | – |

Each leaf question is aligned to 1–2 outcomes. Rubric criteria carry Canvas
`learning_outcome_id`, giving `canvas_alignment` on the criterion. Question alignments come from
`manual/question_outcomes.json` with `source = instructor`.

**Realistic errors** are drawn per question from an error catalogue, weighted by the student's
profile, and each comes with a matching comment. Examples:
- "Sign of the slack variable is reversed: a ≥ constraint needs a surplus (−s), not +s."
- "Forgot the non-negativity constraints x₁, x₂ ≥ 0."
- "Ratio test should skip non-positive column entries; row 2 can't leave."
- "Entering variable: for a max problem in this tableau form, pick the most negative reduced cost."
- "Only two corner points were evaluated; (4, 3) is also feasible and is optimal."
- "Dual constraint direction is wrong for a ≤-constrained max primal."

Each graded submission gets 0–2 question comments and ~50% get a submission comment. ~3 comments
are `teacher_only` (Canvas `hidden`/draft-style note) so the visibility rule has data to protect.

**Materials** (Canvas modules → `course_materials`, kinds from `manual/material_kinds.json`):
8 lecture slide decks (Week 1 Intro & Modeling … Week 8 Sensitivity Analysis), 3 readings
(LP formulation guide, Simplex worked example, Duality notes). They are simple text PDFs with
2–4 pages each.

**Files on disk:** `data/seed/files/{materials,submissions}/…`. Estimated size: 11 materials
(~0.3 MB) + 46 typed HW PDFs (~0.5 MB) + 20 scanned midterms (4 grayscale JPEG pages each at
~60 KB ≈ 5 MB) ≈ **6 MB committed**.

**Seed folder layout:**

### Task 3: Ingestion layer + `npm run seed`
Files: `app/ingest/{canonical,canvas_normalize,canvas_json_adapter,manual_adapter,loader,cli}.py`.
`load(bundle, session)` builds the DB in dependency order. `cli rebuild` deletes and recreates
`data/app.db`. `init_db()` runs the same rebuild when the DB file is missing. Each adapter
declares `capabilities: set[str]`. Delete `app/seed.py`.
Tests: row counts per table; demo ids 1–4 resolve to the right names; re-running rebuild gives
identical counts; `canvas_normalize` unit tests on one fixture each (quiz `submission_data` →
responses, `rubric_assessment` → rubric_scores, hidden comment → `visible_to_student=False`).
Commit `feat(api): Load seed through Canvas JSON and manual adapters`.

### Task 4: Grade calculation (TDD)
File: `app/grading.py`. `compute_grade(groups, rows) -> GradeSummary` where each row has
group id, points_possible, score, workflow_state, excused. Rules (Canvas "current grade"):
only graded, non-excused rows count. Group % = Σscore / Σpossible. If weighting is on, the grade
= Σ(wᵍ·%ᵍ) / Σwᵍ over groups with any counted row. If off, Σscore / Σpossible.
Tests: synthetic cases (renormalization, excused, missing = 0, unweighted, no graded work →
`None`), plus **hand calculations for Alex Kim and Marcus Bell from the generated seed, written
out in the test docstring**. Commit `feat(api): Add Canvas-style current grade calculation`.

### Task 5: Read API + permissions (TDD for permissions)

`app/routers/{home,syllabus,assessments,submissions,grades,materials,files}.py`, schemas.
Tests `tests/test_permissions.py`: one test per rule in §2 and per Review Focus item 1–3 and 5.

## 7. Decisions & risks to confirm

1. **`assignment_groups` as its own table** (15 tables, not 14). It mirrors Canvas and holds the
   weights.

   will show Quiz 3 as past due. Optional mitigation: a `DEMO_NOW` env var (not planned unless you
   want it).
5. ~6 MB of generated PDFs committed to git.
6. Phase 2's `models.py` and `seed.py` are replaced (Phase 2 tests are migrated to the new seed).
