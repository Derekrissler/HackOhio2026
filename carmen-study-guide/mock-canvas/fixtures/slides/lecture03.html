Worked example 3.1

Spot the Bug

An assistant suggests this function for averaging a list of numbers. It looks fine. Read it before you run it.

Suggested code

def average(nums):
    return sum(nums) / len(nums)
Try it

What happens on []? Trace it by hand before you read on.

Answer

ZeroDivisionError. Is that in the spec? If not, it's a bug.

Step 3Check boundaries. Whether an empty list should raise an error, return a value, or never happen is a spec decision. Find it in the spec, or ask, before you accept the code.

Worked example 3.2

Spot the Other Bug

This one passes a quick test. Call it once and it works perfectly. The bug only shows up the second time.

Suggested code

def add_item(item, items=[]):
    items.append(item)
    return items
Try it

Call it twice. What do you get?

Python shell

>>> add_item("apple")
['apple']
>>> add_item("pear")
['apple', 'pear']
Answer

The default list is shared across calls. The second call returns both items.

Why it happens. Python evaluates a default value once, when the def statement runs, not each time the function is called. Every call that leaves out items reuses that same list, so changes from one call leak into the next.

Step 2Trace by hand, and trace more than one call. A single happy-path run would never show this bug.

Section 3.3

Common AI Failure Modes

These patterns show up again and again in assistant-written code. Each one maps to a step on the reading checklist.

Hallucinated APIs

Calls to functions or packages that do not exist.

Catch itStep 5 · check the docs

Plausible but wrong logic

Off-by-one errors and wrong comparison operators in code that reads well.

Catch itStep 2 · trace by hand

Silent except: pass

A bare except: pass hides every failure, so bugs vanish instead of surfacing.

Catch itStep 6 · look for smells

Mutable default arguments

def f(x, items=[]) shares one list across every call.

Catch itStep 2 · trace two calls

Outdated practices

Deprecated functions and APIs from older library versions.

Catch itStep 5 · check dependencies

Overengineering

A factory for a 10-line script. Extra layers make code harder to read and review.

Catch itStep 1 · check the spec

Key takeaways

  • Reading AI-written code is a separate, deliberate step. You own what you accept.
  • Trace real values, including empty inputs and repeated calls.
  • If you can't explain a line, ask or simplify before you accept it.
